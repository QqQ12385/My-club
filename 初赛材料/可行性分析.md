# 可行性分析（初赛提交项）

## 1. 技术可行性

| 环节 | 结论 | 依据 |
|------|------|------|
| 钉钉对接 | ✅ 可行 | 自定义机器人 Webhook 10 分钟可建，支持加签安全（已写连接器、真实发送验证通过） |
| 微信个人号 | ⚠️ 无API → RPA 兜底 | 题目补充明确允许 RPA；Power Automate Desktop 系统自带零成本；控制频率、只读优先、可随时停用 |
| 双通道降级 | ✅ 已实现 | 主通道失败自动切备用（已通过端到端自测） |
| AI 能力 | ✅ 可行 | DeepSeek API 已持有 Key；且有规则引擎兜底 |
| 闭环核心 | ✅ 已跑通 | 接收→归一→展示→回复→通道发送→状态回流，全链路自测通过 |

> 说明：飞书自建应用因个人组织未做企业认证无法调用开放平台 API（21001），
> 已按赛题「至少两个平台」要求改用钉钉 + 微信两平台，接收闭环由 RPA 采集与手动同步兜底实现。

**主要难点与应对预案**：
- 平台事件订阅需公网回调 → 内网穿透（ngrok/花生壳）或轮询兜底；
- RPA 稳定性 → 只作微信通道主力、其余平台备用；故障注入演示真实失败原因与降级路径；
- 平台限流（429）→ 指数退避重试 + 备用通道降级。

## 2. 数据可行性

- 平台消息：官方 API 事件订阅（钉钉）+ RPA 桌面采集（微信），自采自用，无需外部数据集；
- 演示数据：后端内置 9 条跨平台种子消息，断网也可演示完整闭环；
- 消息去重：平台消息按 msg_id、RPA 采集按「发送人+时间+内容」哈希，重放不产生重复。
