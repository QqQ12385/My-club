# 多平台连接器与统一消息管理 — 设计文档（初赛精简版）

> 团队成员：成员A（后端/连接器/AI集成）· 成员B（前端UI/演示）｜赛题 1/A
> 交付日期：2026-11-20

## 1. 问题与方案概述

**痛点**：微信、钉钉等多平台消息割裂，来回切换效率低。
**方案**：构建统一消息中心——连接器层对接多平台（API 主通道 + RPA 备用通道），将各平台消息归一化为统一格式，在 Web 统一入口集中展示；用户在入口内直接回复，系统自动完成格式转换、通道发送、状态回流，形成「接收 → 展示 → 处理 → 发送反馈」完整闭环。叠加 DeepSeek 大模型实现消息智能分类、回复建议与每日摘要。

## 2. 业务闭环流程（核心）

```
平台消息（钉钉 Stream / 飞书 WebSocket 长连接 / 微信 RPA 采集）
        │
        ▼
  ① 归一化层：统一 Message 格式 + 去重(msg_key / 内容哈希) + 落库(SQLite)
        │
        ▼  WebSocket 推送 new_message
  ② 统一入口展示：三栏界面 · 双维筛选 · 待办自动生成
        │
        ▼ 用户回复 POST /messages/{id}/reply
  ③ 发送路由：按 CHANNEL_PLAN 选主通道 → 格式转换 → 发送
        │           主通道失败 → 自动降级备用通道重发
        ▼
  ④ 状态回流：replied → synced，1.1s 内经 WebSocket 推回前端，
     全程写入状态流转时间线（可回溯每一步）
```

> 钉钉、飞书均为**真实双向闭环**：长连接实时推送 → 归一化/AI 分类 → 统一入口实时展示；
> 统一入口回复 → 机器人 OpenAPI 真实回发到群/会话并 @ 对方。

## 4. 核心接口定义

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/auth/login | 登录，返回 token + 用户资料 |
| GET | /api/auth/dingtalk/url · /callback | 钉钉扫码登录（OAuth 授权码换 unionId，自动注册绑定本地账号） |
| GET | /api/messages | 消息列表（平台/状态/关键字三重筛选，按登录账号数据隔离） |
| POST | /api/messages/{id}/reply | 回复：选通道→转格式→发送→降级→回流（钉钉/飞书真实回发） |
| POST | /api/messages/{id}/send-file | 文件发送：钉钉/飞书媒体上传 API 真实发到群/会话；微信走 RPA |
| POST | /api/messages/{id}/recall | 撤回：记录保留、标记已撤回；钉钉侧撤回经 Stream 事件自动同步 |
| DELETE | /api/messages/{id} · /api/messages/clear | 删除单条 / 清空记录（级联清理会话与磁盘文件） |
| GET | /api/messages/export | 导出全部消息记录 CSV（UTF-8 BOM，Excel 直接打开） |
| GET | /api/files/{fid} | 文件下载/在线打开（接收与发送的文件均磁盘留档） |
| GET | /api/contacts · POST /api/contacts/add | 好友清单：聚合各平台联系人 + 手动添加好友（持久化） |
| POST | /api/contacts/send | 向联系人主动发消息（真实发送路由并 @该人） |
| GET | /api/users · PATCH /api/users/{account}/role | 成员管理（仅管理员）：查看账号、切换管理员/普通用户 |
| POST | /api/collector/incoming | 归一化入口：平台回调与 RPA 采集统一打此接口 |
| GET | /api/apps · POST /api/apps/{key}/connect/disconnect/test | 应用连接管理 |
| POST | /api/ai/classify · /api/ai/suggest · /api/ai/summary | AI 分类/建议/摘要 |
| WS | /ws | 推送 new_message / status_update / msg_recalled / thread_update / channel_update |

**统一消息格式（Message）**：`{id, platform, sender, chat, time, day, type(text|todo|recall), content, status, unread, pinned, muted, owner}`；
状态机：`received → processing → sending → replied → synced`（失败 `failed`；撤回 `recall` 保留痕迹）。

**数据隔离与角色**：所有消息挂 `owner`（登录账号）；管理员可见全部并拥有成员管理，普通用户只见自己名下消息——支撑「系统用户区分」要求。

## 5. 关键表结构

| 表 | 关键字段 | 说明 |
|----|---------|------|
| messages | id, platform, msg_key, dedup_key(UNIQUE), conv_id, status, type, owner | 消息主表；conv_id 存钉钉 openConversationId（回发用），dedup_key 兼顾平台ID与RPA无ID场景，owner 做账号数据隔离 |
| thread | msg_id, from_side, text, channel, file_id | 会话上下文；file_id 关联磁盘文件（气泡可点击下载） |
| files | id, msg_id, filename, size, path | 收发文件留档（钉钉机器人 messageFiles/download、飞书 im/v1/messages 资源下载接收，媒体上传发送） |
| contacts | platform, name, chat, owner | 好友清单：自动聚合平台联系人 + 手动添加持久化 |
| users | account, name, role(admin/user), dingtalk_unionid | 账号体系；unionid 绑定钉钉扫码登录，role 区分管理员/普通用户 |
| traces | msg_id, action, detail, ts | 状态流转时间线（闭环可回溯） |
| apps | key, connected, last_sync, success_rate | 平台连接状态 |

## 6. 功能清单（对照老师点评逐项落地）

| 功能 | 实现要点 |
|------|---------|
| 联系人/好友清单 | 按平台+发送人自动聚合，支持手动添加好友、删除好友、向联系人主动发消息 |
| 个体间发消息 | 会话按联系人合并（同一人一个会话），回复经真实发送路由 @对方，非仅机器人问答 |
| 系统用户区分 | 账号体系 + owner 数据隔离 + 管理员/普通用户角色 + 成员管理（角色切换） |
| 多种回复方式 | 文本回复、语音输入（Web Speech API 识别后发送）、AI 自动回复（可开关）、文件发送 |
| 消息撤回 | 网页撤回自己发的消息（保留痕迹）；钉钉侧撤回经 Stream 撤回事件自动同步变灰 |
| 文件双向 | 发送：媒体上传 API 到群/会话；接收：机器人收文件/图片自动下载留档，网页气泡显示缩略图、点击大图预览、可下载 |
| 记录管理 | 删除单条/会话/清空全部、导出 CSV（纯真实数据，无演示种子）、置顶/免打扰 |
| 钉钉扫码登录 | OAuth 授权码模式，扫码后自动注册绑定 unionId，与消息收发共用企业应用 |
| 三平台接入 | 钉钉 Stream + 飞书长连接（WebSocket）+ 微信 RPA，三种协议统一归一化（争取三平台附加分） |

## 6. 双通道设计

| 平台 | 主通道 | 备用 | 理由 |
|------|-------|------|------|
| 钉钉 | API（企业内部应用 Stream 双向收发） | Webhook / RPA | Stream 长连接无需公网回调，个人可建组织，未认证也可稳定收发 |
| 飞书 | API（企业自建应用 WebSocket 长连接） | RPA | 长连接模式免公网回调，`lark-oapi` 的 ws.Client 直接连 |
| 微信 | RPA（Power Automate 桌面自动化） | API | 个人号无开放接口 |

主通道失败（限流/超时/元素定位失败）→ 自动切备用重发 → 仍失败回报真实原因，前端渲染失败气泡并支持手动重试。

> 飞书已在个人自建企业 + 管理员身份下真实接入成功（早期 21001 是未选长连接模式所致，改 WebSocket 长连接后解决）。
> 飞书与钉钉的**事件机制差异**：钉钉群消息全量推送（群聊/单聊/未@均可收）；飞书仅「单聊 + 群内@机器人」推送，群内非@消息不推。故飞书收图片/文件走**单聊机器人**，钉钉走群聊。

   无 Key 时自动降级规则引擎，闭环不中断。
